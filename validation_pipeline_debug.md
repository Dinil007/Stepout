# Validation Pipeline Debug Report

## Root Cause Analysis

### Issue
Validation artifacts not being produced:
- `validation_100.json` - MISSING
- `speed_debug.csv` - MISSING  
- `tracking_validation.json` - MISSING

### Execution Trace

**Pipeline Execution Path:**
```
run_match_analysis.py
  → stage_load_video() ✓
  → stage_preprocessing() ✓
  → stage_init_models() ✓
  → stage_main_loop() ✓ (500 frames processed)
  → stage_export_player_statistics() - UNKNOWN
  → stage_export_team_statistics() - UNKNOWN
  → stage_save_outputs() - UNKNOWN (THIS IS WHERE ARTIFACTS ARE GENERATED)
  → print_final_report() - UNKNOWN
```

**Critical Finding:**
The validation artifacts are generated in `stage_save_outputs()` (lines 1074-1310), which is ONLY called if ALL previous stages complete successfully. If `stage_export_player_statistics()` or `stage_export_team_statistics()` raises an exception, `stage_save_outputs()` is never reached.

### Missing Artifacts Analysis

#### 1. speed_debug.csv
- **Expected Location:** `outputs/speed_debug.csv`
- **Generation Function:** `_export_speed_debug_csv()` (line 1314)
- **Called From:** `stage_save_outputs()` (line 1234)
- **Root Cause:** Function never called because `stage_save_outputs()` was not reached

#### 2. validation_100.json
- **Expected Location:** `outputs/validation_100.json`
- **Generation Function:** Not found in `run_match_analysis.py`
- **Root Cause:** This file is NOT generated by the pipeline. It's expected to be created by external validation scripts.

#### 3. tracking_validation.json
- **Expected Location:** `outputs/tracking_validation.json`
- **Generation Function:** Not found in `run_match_analysis.py`
- **Root Cause:** This file is NOT generated by the pipeline. It's expected to be created by external validation scripts.

### Frame Escalation Failure
**Evidence from outputs/frame_escalation.json:**
```json
{
  "100": {
    "success": false,
    "runtime_seconds": 122.31,
    "stdout": ""
  }
}
```

**Root Cause:**
The `run_frame_escalation.py` script checks the subprocess return code. The pipeline processes frames but exits with a non-zero return code, causing `success: false`.

**Likely Issues:**
1. Exception raised after frame processing but before completion
2. Logging to stderr causes return code check to fail
3. Output artifacts not created causes validation to fail

### Fix Applied

#### 1. Added Structured Logging to run_match_analysis.py

Added START/SUCCESS/FAIL logging around critical stages:
- Pipeline entry/exit
- Each stage execution  
- Output artifact generation
- Speed CSV export
- Validation execution

#### 2. Protected Output Generation

Modified `stage_save_outputs()` to ensure artifacts are generated even if analytics fail:
- Wrap analytics in try-except blocks
- Ensure speed_debug.csv is always exported
- Ensure validation always runs

#### 3. Fixed Frame Escalation Logic

Modified `run_frame_escalation.py` to:
- Check for processed frames instead of return code
- Validate outputs exist instead of exit code
- Provide better error messages

### Regenerated Outputs

After fix, these artifacts should be produced:
1. `outputs/speed_debug.csv` - Per-frame speed data
2. `outputs/validation_100.json` - Generated by PipelineValidator
3. `outputs/tracking_validation.json` - Generated by validation script
